# Applied Programming with C++ - Agent Instructions

This repository contains course assignments for Applied Programming with C++. All C++ compilation and execution must use the **Clang/Clang++ compiler**, not g++.

## C++ Compiler: Clang++

**Required compiler**: `clang++` (LLVM Clang Compiler)

### Installation

#### Windows
Download Clang from the official LLVM releases:
- https://github.com/llvm/llvm-project/releases
- Recommended: `clang+llvm-18.1.4-x86_64-pc-windows-msvc.tar.xz` (or latest)

**Steps:**
1. Download and extract the `.tar.xz` file
2. Add the `bin` folder to your system PATH (System Environment Variables)
3. Verify installation: `clang++ --version`

**Alternative (Windows)**: Use winget if available:
```powershell
winget install -i LLVM.LLVM
```

#### macOS
Clang is included with Xcode Command Line Tools:
```bash
xcode-select --install
```

#### Linux
Clang is available via package managers:
```bash
# Debian/Ubuntu
sudo apt-get install clang

# RHEL/Fedora
sudo dnf install clang
```

## Compilation

**Always use `clang++` instead of `g++`**:

```powershell
# Compile with clang++
clang++ -o program_name source1.cpp source2.cpp

# Run the program
.\program_name.exe  # Windows
./program_name      # macOS/Linux
```

### Example from Assignment 1, Exercise 2.6:
```powershell
cd "Assignment 1\test"
clang++ -o newton_test 2_6.cpp main.cpp
.\newton_test
```

## Guidelines for Code Solutions

When creating solutions for assignments:

1. **Header Files**: Use `.h` extension
   ```cpp
   double newton_Raphson(double initialGuess, double epsilon, int maxIterations = 100);
   ```

2. **Implementation Files**: Use `.cpp` extension, include the header
   ```cpp
   #include "header.h"
   // implementation
   ```

3. **No main() in submission**: Only the `test/` folder may contain main() functions

4. **Compilation**: Always use `clang++` for compiling all examples and solutions

5. **Testing**: Create test programs in the `test/` subfolder for each assignment

## Code Style and Documentation

Keep code **minimal and clean**:
- Only add comments where the code logic is not obvious
- Sparse documentation - no excessive Doxygen/javadoc style comments
- Focus on code that you understand, skip unnecessary elaboration
- Function declarations should be clear enough without extensive documentation
